# 游戏工程接入

此目录保留给唯一的主游戏工程。尚未选择引擎，因此没有伪造工程文件。

## 创建时

- Godot：将 `project.godot` 创建在本目录；提交 `.uid`、资源旁的 `.import`、场景与脚本；忽略 `.godot/`。可以按 `features/player/`、`features/combat/`、`levels/`、`shared/` 分组，让场景、脚本和专属资源靠近。
- Unity：让 `Assets/`、`Packages/`、`ProjectSettings/` 直接位于本目录。提交 `.meta` 与包锁文件；使用编辑器对应的文本序列化及可见元文件设置，再补齐该版本的忽略规则。
- Unreal：让 `.uproject` 位于本目录，提交 `Config/`、`Content/`、`Source/` 等实际项目文件；第三方插件中的必需预编译文件需单独判断是否跟踪。
- 其他引擎：保留其原生布局，不强制套用上述目录。

## 引擎确定后的完成标准

1. 将引擎精确版本、依赖版本和安装步骤写入技术决策。
2. 将这里更新为准确的启动、测试、导出命令和输出路径。
3. 创建最小启动场景，在目标平台运行一次。
4. 检查 Git 不包含缓存，且重新检出后可以重建工程。
5. 有实际可运行项目之后，再添加对应的持续集成与导出脚本。

命名服从引擎规范；通用资源优先使用小写 `snake_case`，C# 类型文件遵循语言规范。避免仅大小写不同的路径。
